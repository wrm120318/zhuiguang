## A. Bug 修复（来自用户反馈截图）

### A1. 【全站·三档】输入框聚焦/悬停时的"矩形方框"【图 1】

> ⚠️ **范围升级（二次）**：用户确认此问题**全站普遍存在**（前台搜索框、评论区、后台所有表单、弹窗、select、textarea……只要输入就出现），**且墨金模式下同样存在**（经典模式用户尚未确认，但根因相同，一并修复）。

**根因（全局规则三档全中——墨金模式并没有豁免）**：

`main.css:131 / 132` 是 **`:root` 全局规则，三档皮肤全部继承**。墨金两档只额外覆盖了两件事——`border-radius: 999px`（胶囊化）和 `.is-focus` 聚焦光环（650-653 / 929-933）——**但从未覆盖"常态"和"hover"的 `box-shadow`**，所以全局描边规则在墨金下照常生效：

| 状态        | 经典暖橘                              | 墨金浅色                                                         | 墨金深色                                                                   |
| --------- | --------------------------------- | ------------------------------------------------------------ | ---------------------------------------------------------------------- |
| **常态**    | L131：白底 + 经典橘 20% 描边 + 12px 圆角    | L131 未覆盖：**经典橘 20% 描边**（写死 `rgba(245,158,11,.2)`，非墨金棕金！）+ 胶囊 | L131 未覆盖：**白底 + 经典橘 20% 描边**（背景仍是 `rgba(255,255,255,.9)` 白色，深色主题下是白块！） |
| **hover** | L132：**100% 实色橘框**                | L132 未覆盖：**100% 实色棕金框**（`var(--zg-primary)`=#BA7517）         | L132 未覆盖：**100% 实色亮金框**（#D4AF37，深色底上极刺眼）                               |
| **focus** | 无覆盖，EP 默认被 L131 的 `!important` 压制 | ✅ 650-653 3px 柔和光环                                           | ✅ 929-933 3px 柔和光环                                                     |

**三个关键发现**：

1. 墨金模式的"方框"来自 **L131 写死的经典橘 20% 描边 + L132 hover 变 100% 实色**——墨金只改了圆角（胶囊）和聚焦，**常态/hover 的描边颜色与墨金棕金调性不符**；
2. 胶囊 999px 圆角用在矮输入框（height≈32px）上，视觉上**接近矩形**，1px 描边看起来就是"矩形框"；
3. **墨金深色输入框背景仍是白色**（`rgba(255,255,255,0.9)` 未覆盖）——深色主题下白块输入框 + 亮金描边，格外突兀。

**修复方案（三档补齐完整的"常态 / hover / focus"三态设计系统，一处 CSS 全站生效）**：

1. **经典模式**（只修描边 bug，不动经典整体风格——守铁律）：
   - hover：100% 实色 → `box-shadow: 0 0 0 1px rgba(245,158,11,0.45) inset`
   - 补 `.is-focus` 柔和光环：
     ```css
     .el-input__wrapper.is-focus,
     .el-textarea__inner:focus,
     .el-select__wrapper.is-focus {
       box-shadow: 0 0 0 3px rgba(245,158,11,0.15), 0 0 0 1px var(--zg-primary) inset !important;
       transition: box-shadow .2s ease;
     }
     ```
2. **墨金浅色**（`.zg-inkgold` 作用域**新增**常态 + hover 覆盖，接上已有的 650-653 focus 光环）：
   - 常态：`background: rgba(255,255,255,0.92)` + `box-shadow: 0 0 0 1px rgba(186,117,23,0.18) inset`（描边换成**墨金棕金**，不再用经典橘）
   - hover：`box-shadow: 0 0 0 1px rgba(186,117,23,0.40) inset`（半透明，不做 100% 实色）
3. **墨金深色**（`.zg-inkgold-dark` 作用域**新增**常态 + hover 覆盖，接上已有的 929-933 focus 光环）：
   - 常态：`background: rgba(255,255,255,0.06)`（深色面板底，**修掉白块 bug**）+ `box-shadow: 0 0 0 1px rgba(212,175,55,0.22) inset`
   - hover：`box-shadow: 0 0 0 1px rgba(212,175,55,0.45) inset`
4. `el-input-number` / `el-date-editor` / `el-autocomplete` 等派生组件内部就是 `.el-input__wrapper`，**同一条规则自动命中**，无需逐个改；
5. **铁律 4 回归**：后台所有表单（用户管理、班级、公告、文章、学科、主题、经验规则等）三档下输入框聚焦/悬停视觉统一，**读写/保存/回显/发布功能不受任何影响**；上线前三档目视检查（铁律 5）。

### A2. 学科编辑：图标仍是 emoji + 背景色杂乱【图 2】

1. **替换图标源**：用 Element Plus Icons（`@element-plus/icons-vue`）的 16 个语义化图标替代 emoji，例如：
   - 📚 → `Reading` / `Notebook`
   - 📐 → `Compass` / `Histogram`
   - 🌍 → `Globe` / `Earth`
   - 🔬 → `Microscope` / `DataAnalysis`
   - ⚗️ → `Flask` / `Experiment`
   - 🧬 → `Cell` / `Connection`
   - 🏛️ → `School` / `OfficeBuilding`
   - 💻 → `Monitor` / `Cpu`
   - 🎨 → `Brush` / `PictureFilled`
   - 🎭 → `MagicStick` / `Star`
   - 📊 → `TrendCharts` / `PieChart`
   - 📝 → `EditPen` / `Document`
   - 🔢 → `Files` / `Operation`
   - 💡 → `Sunny` / `Lightning`
   - 🎯 → `Aim` / `Pointer`
2. **统一背景色**：所有 preset 统一用 `background: rgba(245,158,11,.06)`（半透明暖金），选中态 `background: var(--zg-primary)` + 白色 SVG。SVG 单色 + 统一背景 = 整齐、克制、与整体暖橘金调一致。
3. **emoji 兜底（仅限整组兜底）**：若 EP 图标库无法凑齐 16 个语义+风格统一的图标，则**整组**改为自绘 SVG 或**整组**保留单色处理后的 emoji（`filter: grayscale(1) brightness(0.8)`），不允许组内个别用 emoji 个别用 SVG 的混搭。

### A4. 网站自定义页：输入框圆角过大、内容被覆盖【图 4】

**根因**：`src/styles/main.css:131` 设了 `border-radius: 12px !important` for `.el-input__wrapper`，但截图里输入框明显**远超 12px**——接近 20-24px。排查后发现：

- `el-input` 内部 `el-input__inner` 的 `padding` 配合 wrapper 的圆角，文字在左右内边距被吃掉
- 加上 `show-word-limit` 计数器占了一行，视觉上"挤压"感更强
- 真正的大圆角是 Element Plus 的 `--el-border-radius-base` 变量没重定义，EP 默认用了 4px，但**某些 EP 组件（如 `el-textarea` 的 `resize` 角标）**&#x7EE7;承自 `inherit`，被外层 `border-radius: 18px`（`--zg-radius`）影响

**修复方案**：

1. **在 `:root` 显式重置 EP 圆角变量**：
   ```css
   :root {
     --el-border-radius-base: 8px;
     --el-border-radius-small: 6px;
     --el-border-radius-round: 999px;  /* 仅按钮/胶囊用 */
   }
   ```
2. **统一输入框圆角**：
   - `.el-input__wrapper` 圆角改为 `10px`（更紧凑、不过分圆）
   - `.el-textarea__inner` 圆角 `10px`
   - `.el-input__inner` 的 `padding: 0 12px`（从默认 0 15px 收紧）
3. **避免内容被覆盖**：
   - `show-word-limit` 计数器加 `background: transparent; padding-right: 8px`，不再压文字
   - 文字行高 `line-height: 1.6`（确保不被圆角切掉）

### A5. 登录卡片阴影不自然【图 5 · 用户追加反馈】

**根因**（基于 CSS 定位，无截图像素级判断）：

- 经典模式：`.login-card` 继承 `.glass-strong` → `box-shadow: var(--zg-shadow)` = `0 8px 32px rgba(245,158,11,0.12)`——**单层 12% 橙色 alpha 的"染色阴影"**，落在浅色背景上会显"脏"、像局部污渍，且单层模糊没有层次感。
- 墨金浅色：`.zg-inkgold .glass-strong` = `0 20px 60px rgba(120,90,30,0.18)`——棕黄大阴影，面积偏大、颜色偏深。
- 墨金深色：`LoginView.vue:129` 内联 `0 28px 80px rgba(0,0,0,0.55)`——**又大又重的黑影子**，卡片像悬浮在黑洞里，没有边缘高光，深色模式下质感塌陷。

**修复方案**（"双层阴影 + 高光描边"设计规范，替代单层大阴影）：

1. **统一改为双层结构**：`接触阴影(2px 近距、低透明) + 环境阴影(大半径、中透明)`——贴近真实光照，有层次不浑浊：
   ```css
   /* 经典模式（暖而不脏） */
   .login-card {
     box-shadow:
       0 2px 8px rgba(120, 53, 15, 0.06),
       0 18px 48px rgba(120, 53, 15, 0.14);
   }
   /* 墨金浅色 */
   .zg-inkgold .login-card {
     box-shadow:
       0 2px 8px rgba(120, 90, 30, 0.06),
       0 20px 48px rgba(120, 90, 30, 0.16);
   }
   /* 墨金深色：收暗 + 顶部 1px 高光，避免死黑 */
   .zg-inkgold-dark .login-card {
     box-shadow:
       0 2px 8px rgba(0, 0, 0, 0.25),
       0 24px 64px rgba(0, 0, 0, 0.40);
     box-shadow:
       0 2px 8px rgba(0, 0, 0, 0.25),
       0 24px 64px rgba(0, 0, 0, 0.40),
       inset 0 1px 0 rgba(255, 255, 255, 0.08);  /* 顶部高光描边 */
   }
   ```
2. **同步更新 `--zg-shadow` 系列变量**（B3 色彩系统的 4 级阴影一并按此规范：`shadow-sm/md/lg/xl` 全部双层化），后续所有卡片沿用同一套阴影语言，不再出现"单层大糊影"。
3. hover 抬升（经典 `0 16px 40px`）保留，但同样改为双层（抬升时环境阴影扩大、接触阴影收窄——模拟卡片"离地"）。

**效果预期**：经典模式阴影从"橙色染污"变成"暖调干净"；墨金深色从"黑洞"变成"透亮悬浮 + 边缘高光"，三档统一有质感。

### A6. 网站背景不够亮 / 整体偏暗【图 6 · 用户追加反馈】

**根因**：从截图看当前是经典暖橘模式，body 背景是 `main.css:6-8` 的 `#FFFBEB → #FEF3C7 → #FDE68A` 渐变，本身已经偏亮。但用户觉得"暗"，真正的原因是：

1. **卡片 `.glass` 背景只有 `rgba(255,255,255,0.72)`**，铺在暖色渐变上会把背景色"透上来"，视觉上整体发暖/发暗
2. **卡片边框 `rgba(245,158,11,0.18)` 存在感太强**，橘色半透明边框把卡片和背景糊成一片
3. **Hero 区域又有一层 `rgba(251,191,36,0.12)` 的暖黄渐变叠加**，多层暖色叠加后产生"黄昏感"
4. 与日常办公系统常见的"大白底"相比，追光的暖黄品牌色会让用户本能觉得"不够亮"

**修复方案（提亮但不丢失品牌调性）**：

1. **经典模式卡片提亮**：
   - `--zg-card-bg` 从 `rgba(255,255,255,0.72)` 提升到 `rgba(255,255,255,0.88)`
   - `--zg-card-border` 从 `rgba(245,158,11,0.18)` 降到 `rgba(245,158,11,0.10)`，让边框更隐约
   - `.glass` 加 `backdrop-filter: blur(14px) saturate(140%)`（当前如果已有 glass 则增强），强化毛玻璃通透感
2. **body 渐变尾色往回收**：把 `#FDE68A`（较深暖黄）改成 `#FFF5D6` 或 `#FFFBEB`，保留暖调但去掉"黄昏感"：
   ```css
   :root {
     --zg-bg-from: #FFFDF5;   /* 由 #FFFBEB 提亮 */
     --zg-bg-via: #FFF7E0;    /* 由 #FEF3C7 提亮 */
     --zg-bg-to: #FFEFC2;     /* 由 #FDE68A 大幅提亮 */
   }
   ```
3. **减少 Hero 区域暖色叠加**：`.hero-bg` 的渐变从 `rgba(251,191,36,0.12)` 降到 `0.07`，甚至改成白色微泛金的极淡渐变，让 Hero 卡片更干净。
4. **墨金浅色同步提亮**：
   - `--zg-bg-from` `#FAF8F4` → `#FDFBF7`
   - `--zg-bg-via` `#F5F1E8` → `#FAF6EE`
   - `--zg-bg-to` `#EFE9DC` → `#F5F0E4`
   - 墨金卡片背景也同步提高到 `rgba(255,255,255,0.92)`

**专业意见**：

- **调亮是合适的**，但建议走"暖白/米白"方向，不要直接改成纯白（会丢失追光的品牌辨识度）。
- 提升重点应该放在**卡片不透明度**和**边框存在感**上，而不是把 body 调成白底。
- 预期效果：背景还是温暖的，但卡片像"浮在白瓷上"，整体更干净、现代、符合用户对"亮"的直觉。

### A7. 首页快捷入口 / 学科子站图标背景色杂乱【图 6 · 用户追加反馈】

**根因**：

- 首页快捷入口 `HomeView.vue:32` 的 `defaultQuickLinks` 每个入口都自带 `color` 字段（`#F59E0B` / `#FBBF24` / `#FB923C` / `#FDE68A`），渲染成图标容器渐变背景：
  ```vue
  <div class="qg-icon" :style="{ background: `linear-gradient(135deg, ${ql.color}, ${ql.color}aa)` }">
  ```
- 后台可自定义更多快捷入口，每个都能随便选色；学科 `s.color` 也是后台自定义，截图里就出现了**蓝色（网站说明）、绿色（题库自测）、粉色（网站博客）、棕色（生物）**&#x7B49;与整体暖橘金完全不搭的颜色。
- 结果：同一屏里 8 个快捷入口 + 9 个学科子站 = 十几个彩色方块，像"应用商店"不像"学科平台"，破坏整体高级感。

**修复方案**（统一暖金底色为**默认状态**，后台自定义颜色照常生效——守铁律第 4 条）：

1. **首页快捷入口图标容器**：
   - 默认状态（后台未自定义 `color` 或 `color` 为空）：容器 `background: rgba(245,158,11,0.10)`（暖金浅底），图标用 `var(--zg-primary)`（#F59E0B）
   - **后台自定义了 `color`**：按 `:style="{ background: linear-gradient(135deg, ${ql.color}, ${ql.color}aa) }"` 原逻辑照常渲染——自定义颜色正常生效、不会被默认暖金覆盖
   - hover 态：容器背景变为 `var(--zg-primary)`，图标反白（自定义色时同理取该色为 hover 主色）
   - 实现要点：保留 `defaultQuickLinks` 的 `color` 字段供"无配置时默认值"使用；`displayQuickLinks` 计算属性里若某条 `color` 为空，则前端走暖金默认底——既统一又兼容自定义
2. **学科子站图标容器**：
   - 默认状态（`s.color` 为空）：容器 `rgba(245,158,11,0.10)` + 金色图标
   - **后台给学科配了 `s.color`**：照常按 `s.color` 渲染图标容器渐变——自定义颜色正常生效
   - 即：`sc-icon` 的 `:style` 改为「有 color 用 color、无 color 用默认暖金」的兜底写法，保证后台学科颜色配置始终可用
3. **墨金模式对应默认值**：
   - 墨金浅色默认底：容器 `rgba(186,117,23,0.10)`，图标 `#BA7517`；自定义色仍按自定义渲染
   - 墨金深色默认底：容器 `rgba(212,175,55,0.12)`，图标 `#D4AF37`；自定义色仍按自定义渲染
4. **图标源升级（与 A2 合并）**：快捷入口和学科子站统一使用 EP Icons SVG 或 ZgGlyph 金色 SVG 作为**默认图标**（无自定义 emoji 时）；后台自定义了 emoji/icon 的照常显示自定义图标。

**效果预期**：默认状态下首页从"彩色应用网格"变成"统一暖金图标系统"，高级感立刻提升；同时后台任何自定义颜色/图标配置都照常生效，功能完全正常——既统一又灵活。

### A8. 学科子站导航栏选中态：色块 → 底部线【图 7 · 用户追加反馈】

**根因**：`SubjectView.vue:580` 的 `.sub-tab.on` 选中态是 `background: var(--zg-primary)`（整块色块）。而**正常导航栏在墨金模式下已经实现为"底部金线"**（`main.css:640-647`，`.nav-link::after` 下划线展开动画），但 `.sub-tab` 从未被墨金模式覆盖，导致学科子站导航选中仍是色块、与全局导航不一致。

**修复方案**（把 `.sub-tab` 对齐 `.nav-link` 的底部线语言）：

1. **墨金模式**（`.zg-inkgold` / `.zg-inkgold-dark`）下给 `.sub-tab` 加同款底部金线：
   ```css
   .zg-inkgold .sub-tab { position: relative; background: transparent !important; }
   .zg-inkgold .sub-tab::after {
     content: ''; position: absolute; left: 14px; right: 14px; bottom: 4px; height: 2px;
     background: linear-gradient(90deg, transparent, var(--zg-primary), transparent);
     transform: scaleX(0); transform-origin: center;
     transition: transform .25s cubic-bezier(.22,1,.36,1);
   }
   .zg-inkgold .sub-tab.on,
   .zg-inkgold .sub-tab:hover { color: var(--zg-primary) !important; }
   .zg-inkgold .sub-tab.on::after,
   .zg-inkgold .sub-tab:hover::after { transform: scaleX(1); }
   ```
2. **经典模式**：正常导航栏 `NavBar.vue:291` 本来就是色块选中，学科子站保持色块即可——两边一致，不动 `:root`（守铁律）。若用户希望经典模式也统一改底部线，说一声即可纳入。
3. 深色档 `.zg-inkgold-dark` 同样覆盖一份（换 `--zg-primary` 为深色档金 `#D4AF37` 语义变量，规则体相同）。

**效果预期**：学科子站导航与全站导航语言统一，选中态从"厚重色块"变成"轻盈金线 + 文字变金"，更现代、更精致。

### A9. 排行榜奖牌：第二/三名没数字 + 图标选择原则【图 8 · 用户追加反馈】

**根因**：`LeaderboardView.vue:34` 的 `medal(i)` 返回 🥇🥈🥉，经 `ZgGlyph.vue:41` 映射：

```js
'🥇': 'GoldMedal', '🥈': 'Medal', '🥉': 'Medal',
```

**第二、三名都映射到同一个 `Medal`**——Element Plus 的 `Medal` 图标是一个不带数字的普通奖牌轮廓，导致墨金模式下 🥈🥉 渲染成同一个无数字图标，既丢了名次信息，也谈不上美观。这是 3.0 去表情化时的映射质量问题。

**修复方案**（奖牌专项 + 图标选择原则）：

1. **奖牌改为自绘带名次 SVG**（推荐）：EP 图标库没有"带数字的金银铜奖牌"，强行用 `Medal` 一定丢信息。改用三个自绘 SVG：
   - 🥇 金牌：`#FFD700` 金 + 白字 "1"
   - 🥈 银牌：`#C0C0C0` 银 + 白字 "2"
   - 🥉 铜牌：`#CD7F32` 铜 + 白字 "3"
   - 放进 `ZgGlyph` 的映射（或新建 `ZgMedal.vue` 组件），墨金模式下渲染这三个自绘 SVG；经典模式保留原 emoji。
   - 这样既保留名次数字、又有金银铜质感区分，比原 emoji 更高级。
2. **图标选择总原则（适用于 A2 / A7 / B10 等所有 emoji→SVG 替换）**——写入文档作为硬约束：
   - 替换 emoji 的目的是**让网站更美观、更高级**，不是为替换而替换；
   - 每个映射都要选**语义准确、视觉好看**的图标；找不到合适的，**宁可保留原 emoji 或自绘 SVG**，也不能用语义偏差/丑陋的图标凑数；
   - **同一组图标必须风格统一**（全 EP / 全自绘 / 全 emoji，组内不混搭），自绘 SVG 统一线宽、圆角、填充风格；
   - 自绘 SVG 优先用于"EP 图标库无法表达"的场景（奖牌名次、品牌 logo、学科特色符号等）；
   - 替换后要在经典/墨金浅/墨金深三档下都目视检查一遍，确保不丢信息、不变丑。
3. **回溯 ZgGlyph 现有映射**：3.0 批量去表情化时可能有其它"凑数映射"（如 ❤→Medal、🔬→MagicStick 等语义不准的），本轮一并审视修正。

**效果预期**：排行榜前三名有清晰的金银铜奖牌 + 名次数字；全站图标替换回归"美观高级"的初衷，不再出现"为去 emoji 而变丑"。

## D. 铁律（不变）

1. **经典暖橘 `:root` 一律不改**——3.0 之后用户已确认这是"主基调"，新样式只在 `.zg-inkgold` / `.zg-inkgold-dark` 作用域（针对墨金模式的现代化）。
2. **不碰架构/路由/角色字符串/后端**——只改 UI 层。
3. **只有用户说"做"才开始改文件**——本轮只规划。
4. **【超级管理员后台联动·硬性要求】** 改界面样式时，**必须同步保证超级管理员后台的各项自定义功能一起修改、始终生效、功能正常**。要求是"不仅不破坏，还要保证功能正常"：
   - 后台可自定义的入口（快捷入口 quickLinks、学科颜色 s.color、站点配置 siteConfig、公告、主题切换等）在新样式体系下**该自定义的还能自定义**——后台的增删改查、保存、回显、发布全链路必须正常工作；
   - 新样式提供的"统一默认呈现"（如 A7 暖金底色）是**默认状态**：当后台未自定义或字段为空时走默认；**一旦后台自定义了值，自定义值必须照常生效显示**（例如后台给某学科配了蓝色，前台该学科图标就按蓝色渲染，不会被默认暖金覆盖）；
   - 任何涉及后台 UI 的改动（后台的输入框、弹窗、开关、表格、图标选择器等）必须与新样式保持一致并回归验证；
   - 改动上线前要**逐项核对后台自定义功能**（配置 → 保存 → 发布 → 前台生效 → 回显）这条完整链路完好，再做交付。
5. **【图标替换美观原则】** 替换 emoji / 图标的目的是**让网站更美观、更高级**，不是为替换而替换。硬约束：
   - 每个替换都要选**语义准确、视觉好看**的图标；找不到合适的，**宁可保留原 emoji 或自绘 SVG**，绝不用语义偏差/丑陋的图标凑数（如 🥈🥉 都塞同一个无数字 Medal）；
   - 自绘 SVG 优先用于"EP 图标库无法表达"的场景（奖牌名次、品牌 logo、学科特色符号）；
   - 替换后必须**在经典/墨金浅/墨金深三档下都目视检查**，确保不丢信息、不变丑。
6. **【图标视觉风格统一】** 同一类/同一组的图标**必须风格统一**，不能出现"有的是 EP 线性图标、有的是 emoji、有的是自绘"的混搭——混搭是视觉杂乱的根源，比保留 emoji 更难看。硬约束：
   - 一组图标（如 16 个学科图标、首页快捷入口、排行榜奖牌、后台导航等）要么**全部用 EP 图标库**、要么**全部自绘 SVG**、要么**全部保留 emoji**，组内不混搭；
   - 如果 EP 图标库凑不齐一组语义+风格都统一的，就**整组自绘 SVG**（保证线宽、圆角、填充风格一致），不要"能凑的用 EP、凑不齐的塞个 emoji"；
   - 跨组之间也要风格协调（比如学科图标和快捷入口图标都用线性/都用填充，不要一组线性一组填充）。
