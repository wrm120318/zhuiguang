## 1. 七项问题诊断与方案

### 1.1 加载界面 & 登录界面能高级一些
**现状（已定位）：**
- 加载态只有 `src/App.vue` 里一行 `.boot`（`✨ 追光加载中…`，flex 居中文字，80vh），**全项目无 LoadingView、无骨架屏**（`main.css:120` 的 `.skeleton` 是死代码零引用）。`index.html` 仅有 `<div id="app"></div>`，无预渲染 loader → 首屏白屏到 `.boot` 出现之间有空白。
- 登录页 `src/views/LoginView.vue` 有独立卡片（`.login-card.glass-strong`），但**自带 3 个 `.lb-orb` 橘黄大光斑**（`LoginView.vue:116-119`）。墨金的压制规则只认 `.zg-orb`（`main.css:451-452`），**不认 `.lb-orb`** → 墨金下登录页仍飘着 3 个 opacity .4 的橘黄光斑并持续动画，与站内其它近乎静止的灰白风格割裂。

**方案（双模式：经典也升级，已批准例外；墨金额外用沉稳金）：**
- 加载：把 `.boot` 升级为**品牌启动屏**——居中 `LogoMark` 星芒 SVG + 极淡金色呼吸/微光 + 一条细金色不确定进度条 + 衬线「追光加载中…」。主题感知（墨金用沉稳金、经典用暖橘）。可选：在 `index.html` 的 `#app` 内放一个极简内联品牌占位（同色背景 + 星标），**消除首屏白闪**。
- 登录：双模式收敛 `.lb-orb`（或改名复用 `.zg-orb` 规则）——光斑降透明度并停动画；卡片加更精致的发丝描边与柔和投影；极淡品牌水印提升质感。墨金用沉稳金描边、经典用暖橘描边（同范式不同色温）。

### 1.2 首页模块纯白突兀（尤其「网站公告」）
**现状（已定位）：**
- 首页 `HomeView.vue` 模块为硬编码 6 段，背景全靠全局 `.glass`（`main.css:64`）。墨金把 `.glass` 抬到 `rgba(255,255,255,0.92)`（`main.css:455-460`），叠在墨金暖灰米底（`main.css:449`）上≈`#FDFDFC` 肉眼纯白 → 与底色断层「突兀」。
- 「网站公告」`.announce-bar`（`HomeView.vue:102`）是**通栏扁条、满宽、仅 12px padding**，白色面积集中最扎眼；且 `main.css:459` 用 `!important` 把它的暖橘描边 `rgba(245,158,11,.25)`（`HomeView.vue:171`）覆盖成中性灰 → 白块失去暖色包边，直接「漂」在页面上。
- 根因再深一层：`--zg-card-bg`/`--zg-card-border` 在 `html.zg-inkgold`（`main.css:440-444`）**未重定义**，墨金是用"新增规则"而非"改变量"实现，变量与渲染脱节。

**方案（`.zg-inkgold`）：**
- 在 `html.zg-inkgold` 重定义 `--zg-card-bg` 为**带金调的半透表面**（如 `rgba(255,255,255,0.72)` 或极淡金 `rgba(186,117,23,0.05)`），`--zg-card-border` 为**细金发丝**（`rgba(186,117,23,0.16)`）。一处改动，所有 `.glass` 卡片统一修复，且恢复暖色包边。
- 单独给 `.zg-inkgold .announce-bar` 设金调表面 + 金描边 + 更克制内距，让它读作「高级金调条」而非「白块」。

### 1.3 手机端通知中心功能缺失
**现状（已定位）：**
- 通知中心唯一触发器是 `NavBar.vue:163-165` 的铃铛（包在 `el-badge`）。但 `NavBar.vue:363` 在 `@media (max-width:768px)` 用 `display:none !important` 把 `.bell` 整个隐藏 → **移动端通知中心变成"代码在但永远打不开"的死功能**（数据层 `loadNotices()` 照常拉，`unread` 有值，用户却看不到入口/未读数）。
- 移动抽屉 `.d-list`（`NavBar.vue:203-217`，12 项）与 `MobileTabBar.vue`（5 tab）都**没有「通知中心」入口**。

**方案（功能修复，改 `NavBar.vue` 模板，不碰铁律）：**
- 在移动抽屉 `.d-list` 追加「通知中心」项（照抄 `字体设置` 写法：先 `drawerVisible=false` 再 `noticeVisible=true`），带未读红点/数字徽标。
- 备选：直接放开 `.bell` 在移动端显示（但窄屏空间紧，优先选抽屉入口）。
- 顺带：站内信 `.msg-bell`（`NavBar.vue:144-146`）移动端未隐藏，可一并检查是否也要补入口。

### 1.4 选择栏目的侧边栏「残留黄」（移动抽屉 & 后台侧栏）
**现状（已定位）：**
- 移动端菜单抽屉：`main.css:266` `.el-drawer{background:#FFFBEB}` + `main.css:285` `.el-drawer__body{background:#FFFBEB}` 硬编码暖米黄；墨金只覆盖外壳 `main.css:472`，**`__body` 仍是 `#FFFBEB`**。
- 后台 `.sidebar` 移动态（`AdminLayout.vue:175`）显式写死 `background: rgba(255,251,235,0.98)` + 暖橘外发光；墨金侧栏美化被锁在 `@media (min-width:961px)`（`main.css:475`），移动端拿不到。
- 深层：`store/theme.ts` 把暖色变量以内联样式写到 `<html>`，墨金段从未改 `--zg-bg-from` 等，body 底色在墨金下仍是暖黄，`0.96/0.98` 半透明会微量透出加重黄感。

**方案（`.zg-inkgold`，经典不动）：**
- 补 `.zg-inkgold .el-drawer__body { background: rgba(250,248,244,0.96) !important; }`（与外壳一致）。
- 用 `html.zg-inkgold .sidebar { background: <中性> !important; border:1px solid rgba(186,117,23,.18) !important; box-shadow:... }`（`html.` 前缀 + `!important` 压过 scoped `[data-v]` 注入顺序）让**移动端也能拿到**墨金中性表面，去掉暖橘外发光。
- 抽屉内部 `.d-search/.d-user/.d-item/.d-subj` 的 `rgba(245,158,11,…)` 在墨金下可统一降到更克制的金调（可选）。

### 1.5 通知中心背景「残留黄」
**现状（已定位）：** 与 1.4 同源——通知中心抽屉 `NavBar.vue:261` 的 `__body` 仍是 `main.css:285` 的 `#FFFBEB`，占可见区 90%+；条目 `.notice-item`（`NavBar.vue:347-352`）是 6%–20% 琥珀底，墨金只加了圆角/未读金环（`main.css:488-489`），**没换色**。

**方案（`.zg-inkgold`）：**
- `.zg-inkgold .el-drawer__body { background: rgba(250,248,244,0.96) !important; }`（同 1.4）。
- `.zg-inkgold .notice-item { background: rgba(31,36,48,0.04) !important; }` 中性底；`.unread` 保留金环（`main.css:489` 不动）；`.n-type` 等标签金调可保留作点缀。

### 1.6 弹窗上下各一个「矩形色块」
**现状（已定位）：**
- `main.css:170` `.el-dialog__header` 铺 `rgba(255,251,235,0.8)` 渐变；`main.css:221` `.el-dialog__footer` 铺同款；`main.css:216` body 透明 → 弹窗被切成「暖黄条 / 透明 / 暖黄条」三段。
- 墨金把 `.el-dialog` 改成 `rgba(250,248,244,0.82)` 冷灰半透 + `backdrop-filter`（`main.css:464-471`），但**头/尾的暖黄层没重置**（仅 `main.css:496-498` 改了 border）→ 冷灰底 + 暖黄条 = 色相明度双差，加上 `backdrop-filter` 让 0.8 暖黄层显成实色块。
- 经典模式弱化版（顶部同色不可见，底部一条偏白带）；墨金下两块都明显。

**方案（`.zg-inkgold`，经典不动）：**
- `.zg-inkgold .el-dialog__header` / `.el-dialog__footer` / `.el-message-box__btns { background: transparent !important; }`（仅保留 `border` 分隔线，`main.css:496-498` 已有）。一步消去两块。
- 经典模式如也想清理，可作为独立授权项（会碰基础 CSS，需你确认）。

### 1.7 导航选中「色块」→「下面一条线」
**现状（已定位）：**

### 1.8 输入框聚焦「橘黄矩形框」
**现状（已定位）：**
- 全局（非墨金）`main.css:131` 给 `.el-input__wrapper/.el-textarea__inner/.el-select__wrapper` 设 `box-shadow: 0 0 0 1px rgba(245,158,11,.2) inset`（淡橘内描边），hover 升为 `var(--zg-primary)`（橘黄）；Element Plus 原生聚焦光晕用 `--el-color-primary`（经典橘黄 `#f59e0b`），二者在经典下本就如此。

## 2. 系统性根因与统一样式规范

### 2.1 四条系统性根因（按此顺序修，避免反复打补丁）
1. **墨金「只覆盖父容器、漏覆盖 EP 子元素」** → 1.4/1.5/1.6。检查清单：`.el-drawer`↔`.el-drawer__body`；`.el-dialog`↔`__header`/`__footer`/`__btns`。
2. **暖色硬编码散落基础段 + 组件 scoped，墨金够不到** → 1.2/1.4/1.7。`#FFFBEB`/`rgba(255,251,235,…)`/`rgba(245,158,11,…)` 写死；scoped `[data-v]` 使全局墨金规则因注入顺序落败 → 必须用 `html.zg-inkgold` 前缀 + `!important`。
3. **媒体查询错配** → 1.3/1.4。`.bell` 在 ≤768px 被隐藏；墨金侧栏美化锁 ≥961px，移动端缺失。
4. **主题变量与实际渲染脱节** → 1.2/1.4 最深层。`html.zg-inkgold` 未重定义 `--zg-bg-from/via/to`、`--zg-card-bg`、`--zg-card-border`、`--zg-primary`，致 body 底、`.glass` 卡、全部琥珀描边在墨金下仍是暖色系。

### 2.2 墨金色板变量补全（一次性消解硬编码）
在 `html.zg-inkgold`（建议放在 `main.css:440` 附近）重定义：
```css
html.zg-inkgold {
```

## 7. 风险与缓解

| 风险 | 缓解 |
|------|------|
| scoped `[data-v]` 注入顺序导致墨金规则被组件样式覆盖 | 统一用 `html.zg-inkgold` 前缀 + `!important` |
| 重定义 `--zg-primary` 为深金，按钮/徽标对比度下降 | 实施前核对主要按钮文字色（确认用 `#fff` 或深字），必要时单独兜底 |
| 启动屏/登录改出"过度设计" | 克制：微光 + 细线 + 留白，不堆特效 |
| 移动通知入口与既有 `.msg-bell` 重复/冲突 | 入口只开一个（抽屉项），徽标复用 `unread` |
| 经典模式因「变量重定义只在 inkgold」而保持原样 | 变量层写在 `html.zg-inkgold` 下，不影响 `:root` |
