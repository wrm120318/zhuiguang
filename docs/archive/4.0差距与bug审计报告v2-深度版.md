## ⓪ 一句话总结

**第一轮漏掉的总根因是：`theme.ts` 用内联样式把后台主题的橘色主色写进 CSS 变量，把 `main.css` 里墨金皮肤的棕金重定义整个击穿了——墨金模式下"一半橘、一半棕金"的大混杂，源头在这。** 叠加 42 个文件 200+ 处硬编码橘色不随皮肤转换，以及 B 类现代化"定义了变量但业务视图基本没用"，构成了你看到的一大堆界面 bug。

## 一、🔴 P0 · 新发现 · 架构级总根因

### BUG-01【墨金主色被 theme.ts 内联样式击穿】⭐ 本轮最重要发现

**机制链（三段证据咬合）：**

1. `src/store/theme.ts` L11-18，`applyTheme()` 每次加载**无条件**用内联样式写入变量：
   ```js
   root.style.setProperty('--zg-primary', c.primary)      // ← 后台主题的 primary
   root.style.setProperty('--zg-primary-2', c.primary2)
   root.style.setProperty('--zg-accent', c.accent)
   root.style.setProperty('--zg-radius', c.radius + 'px')
   root.style.setProperty('--zg-blur', c.blur + 'px')
   // … bgFrom/bgVia/bgTo 同样
   ```
2. `src/styles/main.css` 墨金皮肤的重定义**全部没有 `!important`**：
   - L443-445（墨金浅）：`--zg-primary: #BA7517; --zg-primary-2: #C8922E; --zg-accent: #D4AF37;`
   - L450-451：`--zg-radius: 20px; --zg-blur: 18px;`
   - L749-751（墨金深）：`--zg-primary: #D4AF37; --zg-primary-2: #E6C66E; --zg-accent: #F1D99B;`
3. CSS 优先级规则：**内联 style 永远赢过不带 `!important` 的 class 规则**。
4. `src/views/admin/ThemeView.vue` L7：默认主题 `primary: '#f59e0b'`（亮橘）；且 L58-61 切换 designMode 到"墨金学术"时**色板完全不联动**；L15 `presetColors` 8 个预设全是橘黄系，无墨金色系。

**后果（墨金模式下实际渲染）：**
- 全站所有用 `var(--zg-primary)` 的组件（main.css 里 60+ 处：主按钮渐变 L590/898、导航选中 L616/924、分页 L573/881、loading L561/869、focus 光环 L580/888、下拉/开关/滑块…）→ **显示后台的橘色 #f59e0b**
- 而墨金专属规则里硬编码 `rgba(186,117,23,…)` / `#BA7517` 的地方（弹窗、抽屉、消息、卡片边框等几十处）→ 棕金色
- **同一屏幕上橘、棕金两种主色并存** → 这就是"界面一堆 bug"的最大来源
- 连带击穿：墨金设计圆角 20px → 被后台默认 18px 覆盖；毛玻璃 18px → 16px；`--zg-primary-2/--zg-accent` 同理

**旁证**：bright 提亮档的 `--zg-bg-from/via/to` 在 L727/L1032 **加了 `!important`**——说明团队曾撞过同一个内联覆盖问题，但只修了背景三个变量，**主色/圆角/毛玻璃五个变量漏修了**。

**修复方案（双保险，约 30 分钟）：**
```css
/* main.css 墨金浅 + 深两档，变量声明补 !important（照抄 bright 档先例） */
html.zg-inkgold { --zg-primary: #BA7517 !important; --zg-primary-2: #C8922E !important;
  --zg-accent: #D4AF37 !important; --zg-radius: 20px !important; --zg-blur: 18px !important; }
html.zg-inkgold-dark { --zg-primary: #D4AF37 !important; … 同理 }
```
同时 `theme.ts` 的 `applyTheme()` 在 `c.designMode === 'inkgold'` 时**跳过** primary/primary2/accent/radius/blur 的 setProperty（墨金下这些归皮肤管，后台色板仅经典模式生效——需要和"后台自定义优先"的铁律4权衡：建议方案是墨金模式下把后台色板作为"微调"仍生效但默认值改成墨金色系，见 BUG-13）。

## 二、🔴 修正第一轮结论 · A1 其实只做了一半

### BUG-05【A1 输入框三态：经典档 hover/focus 未修】（第一轮误判为"已正确"）

**4.0 文档 A1 修复方案第 1 条（经典模式）要求**：hover 从 100% 实色改为 45% 半透明 + 补 `.is-focus` 柔和光环。

**代码现状（main.css）：**
- L132（`:root` 全局，经典档生效）：`.el-input__wrapper:hover { box-shadow: 0 0 0 1px var(--zg-primary) inset !important }` → **仍是 100% 实色框**，未改 45%；
- 经典档**没有任何 `.is-focus` 光环规则**（全站只有墨金浅 L670-672、墨金深 L978-980 有）→ 经典模式聚焦态仍是被 L131 `!important` 压制的 EP 默认，文档点名的"聚焦无光环"问题在经典档依旧存在；
- ✅ 墨金浅档三态完整（L662-673：常态 669 捕获 hover 40% 棕金、focus 3px 光环）；✅ 墨金深档完整（L970-981）。

**结论修正**：A1 = **墨金两档 ✓ / 经典档 ✗（hover 实色 + focus 无光环）**。

### BUG-17【深色档变量块被浅色档整体压制】⭐ 修复 BUG-01 时发现的隐藏 P0

**两轮审计均漏掉的隐藏级联缺陷。** BUG-01 修复 `!important` 后，用 headless Chrome `getComputedStyle` 实测线上墨金深色档仍呈现"浅档值"：`--zg-text` 解析成深棕 `#2B2620`（深底深字不可读）、`--zg-primary` 解析成浅档棕金而非深档亮金 `#D4AF37`。

**根因（CSS 特异性级联，与 !important 无关）：**
- `html.zg-inkgold { … }` 选择器特异性 = (0,1,1)（一个类 .zg-inkgold + html 元素）；
- 原深色档块 `.zg-inkgold-dark { … }` 特异性 = (0,1,0)，**低于浅档**；
- 两者同带 `!important` 时仍按特异性决胜 → **深色档变量块被浅色档整体覆盖**，深色模式从未按设计意图生效（此前"看起来能用"实为浅档值在撑）。

**修复（main.css）：** 深色档选择器升级为 `html.zg-inkgold.zg-inkgold-dark`（特异性 0,2,1，稳压浅档 0,1,1）；提亮深档块同步升级 `html.zg-inkgold.zg-inkgold-dark.zg-inkgold-bright`（0,3,1）。已用 headless Chrome 回归验证：深档 `--zg-primary=#D4AF37 / --zg-text=#F3EBD9 / --zg-bg=#1B1710`，提亮档 `#241F16`，文字可读性达标。

> 教训：`!important` 只解决"内联 vs 类"优先级，不解决"同类之间特异性"。深/浅两档变量块必须保证深档选择器特异性 ≥ 浅档，否则深档永远不生效。

## 五、🟠 P1 · 新发现 · B 类现代化"定义了、没用上"（BUG-07~11）

### BUG-07【B2 字号阶梯未落地 → 字号缩放功能大面积失效】
- `:root` 定义了完整 `--zg-fs-xs~2xl`（含 `--zg-fs-scale` 用户可调缩放，main.css L17-25），NavBar 有字号调节入口（`.sp-font-btn` L310-311）；
- 但 **53 个 vue 文件仍硬编码 `font-size:13px/14px/15px…`**：MonitorView 40 处、QueryCreateView 40、SubjectView 37、ThemeView 36、AuditView 31、QuizReportView 26、UsersView 20、ProfileView 20、AdminLayout 20、DashboardView 19、QuizListView 18、QuizTakeView 18…
- `--zg-fs-*` 仅 **11 个文件**采纳（多为新组件）。
- **后果是功能级的**：用户调节字号时，走变量的文本会缩放，53 个文件的硬编码文本**纹丝不动**——页面字号忽大忽小、参差不齐。

### BUG-08【B3 色彩/阴影/间距系统未落地】
- `--zg-shadow-sm/md/lg/xl`、`--zg-gray-*`、语义色 `--zg-success/warning/error/info`、`--zg-space-*` 定义齐全；
- 但全站采纳仅 **4 个文件 ~10 处**（ZgState/ZgTimeline/SubjectsView/PracticeTakeView，基本是组件自用）；业务视图全部硬编码 rgba 灰和 box-shadow。B3 = 只有骨架没有血肉。

### BUG-09【B5 品牌空态只接入 4 处】
- ZgState（五类品牌插画空态）仅接入 FavoritesView / SearchView / NotFoundView / SubjectsView；
- **29 个文件**仍用旧"暂无"文字 / el-empty（MessagesView 5、GuideView 6、QuizListView 5、MonitorView 5、SubjectView 8、BlogListView 2…）。

### BUG-10【B9 无障碍基本未落地】
- `aria-*` 仅存在于 **7 个组件文件**（NavBar 6 处、ZgState 5 处、LogoMark/ZgStepper/ZgSparkline/ZgAvatar/ZgGlyph 各 1）；**50+ 业务视图零 aria**；
- `:focus-visible` 键盘焦点轮廓仅墨金两档有（L580/888），**经典档无**——键盘用户在经典模式下无焦点指示。

### BUG-11【B8 移动端部分落地】
- `env(safe-area-inset-*)` 仅 3 个文件（AdminLayout/MobileTabBar/main.css），未全站铺开；
- 底部 sheet 弹窗、下拉刷新、左滑操作未逐视图接入（4.0 记录在案的 B7 余量：长表单自动保存草稿、占位符浮动动画、多步步骤指示器也仍未做——只有 useAutoSave.ts 文件存在）。
