## 1. 根因诊断（已实测排查，非猜）

### 1.1 字体："早上好没衬线 / 用户名有但巨难看" → 是真实 bug，不是错觉（此前诊断有误，已更正）
- **已实测（证据）**：
  - `public/fonts/noto-serif-sc-{600,700,800}.woff2` 三文件 magic 均为 `wOF2`，**字体文件本身有效**。
  - `main.css` L669-672 规则 `.zg-inkgold .hero-title { font-family:'Noto Serif SC','Songti SC','SimSun',serif !important }` 把衬线挂到了 `.hero-title`（父级），而"早上好"=`.hero-greet`、"用户名"=`.hero-name` 都是它的子 span → **两者本应继承衬线**。规则写法没错。
  - **但 `main.css` L6/L13/L20 三个 `@font-face` 全部是 `font-display: swap`** —— 这是我亲手写的、制造首屏闪烁的元凶。
- **真因（CJK 首屏闪烁的精确机制）**：
  - `swap` 在字体未就绪时先显示**回退字体**。回退栈是 `'Noto Serif SC','Songti SC','SimSun',serif`；首屏三者都没下载完 → 落到通用 `serif`（即 Times）。
  - **Times 没有中文字形** → 浏览器必须把中文替成系统 CJK 字体；而现代 Windows/macOS 上这个替补基本是**无衬线中文（微软雅黑 / 苹方）**。
  - 于是"早上好"首屏就渲染成**无衬线中文** = 用户看到的"**根本没衬线**"。这是真实的无衬线回退，**不是加载时序造成的错觉**（我上一版把机制说成"系统宋体"也错了，实为无衬线 CJK 替补）。
  - "用户名"是视觉焦点，等字体加载完你才看到**真衬线**，但它当时是 **700–800 粗体衬线**（L245/L252）→ 又重又笨 = "**巨难看**"。
  - "各页 logo 小标题好看"：同样走这条衬线规则，但它们**字号小（16–28px）、字重轻（600/700）**，衬线在小字下显精致；且你点进去时字体早缓存好、**根本不闪**，所以你从没在 logo 上看到那个无衬线闪屏 → 对比之下"首页不如 logo 好看"。
  - "其他也根本没衬线"：首页 section-title / brand-name 同样在首屏被无衬线替补闪了一下，机制同上。
- **结论**：bug 是**真实的**——`swap` 让中文在首屏落到无衬线替补（早上好没衬线）+ Hero 800 粗体衬线笨重（用户名巨难看）。此前"规则正确、只是错觉"的诊断是错的。根治＝**preload 让字体先于首屏到位 + Hero 字重降到与 logo 同款的 600 优雅档**。

### 1.2 矩形阴影："被框在某个区域里" → 每个区块各自带投影的白卡，而非外部容器
- **已实测**：`.zg-container { max-width:1240px; margin:0 auto; padding:0 24px }`、`.page { padding:24px 0 80px }` —— **本身无背景、无阴影**。不存在"把整页框住的外部容器"。
- **真因**：当前墨金首页里，**Hero / 公告 / 快捷入口 / 学科子站 / 美文** 每个区块都是「近白半透明卡（`rgba(255,255,255,.9+)`）+ `1px` 金边 + `--zg-shadow` 双层投影（`0 2px 8px + 0 16px 44px`）」。一堆浮在米色 `#FAF8F4` 底上的"白贴纸矩形"，彼此互不融合 → 视觉上像"被框在一个个矩形区域里"，整页缺乏流动感与整体感。
- **结论**：不是 bug，是**材质语言与版式组织的问题**——每个元素都是孤立白盒子。

### 1.3 "电脑端比较空" + "整体不美观"
- 当前桌面端：`max-width:1240px` 居中，Hero 独占一大块后，下方公告/快捷/学科/美文是**单列长卷**往下铺，横向利用率低、留白不均 → 显空。
- 材质单调（全站同一种白卡），无层级、无节奏 → 不高级。

## 2. 设计方向：「温润如瓷」材质系统（墨金模式）

### 2.1 材质核心（瓷 = 暖、细腻、柔润光泽）
摒弃此前的"液态玻璃/琉璃（冷、折射、科技感）"路线，改为**温润象牙瓷**：
- **瓷体（表面）**：暖白象牙渐变，**只比页面底色略亮一档**（而非刺眼纯白），如 `linear-gradient(158deg,#FFFDF8 0%,#FBF5EA 100%)`，带极淡暖色，杜绝"白贴纸"感。
- **釉光（关键高级感来源）**：
  - 顶部 `inset 0 1px 0 rgba(255,255,255,.9)` —— 光掠过瓷沿的高光；
  - 一道极柔的斜向釉面光泽（大半径 `radial/linear` 高光，透明度极低），模拟光线打在釉面上的温润反光。
- **多层柔影（让瓷"浮"起来，而非"框"起来）**：`0 1px 2px rgba(120,90,30,.05), 0 10px 30px rgba(120,90,30,.10), 0 30px 70px rgba(120,90,30,.10)` —— 多层、低透明度、大扩散 = 轻柔漂浮感，不再是硬边矩形投影。
- **金边（克制）**：`inset 0 0 0 1px rgba(186,117,23,.10)` + 顶部一道 `0 1px 0 rgba(212,175,55,.22)` 发丝金线，**不是霓虹 2px 金光线、不要流光**（上一版被批"套路廉价"）。

### 2.2 材质层级（解决"一堆白盒子"）
不再让所有区块同款白卡，而是分三级材质，形成节奏：
- **L1 主角 · Hero 瓷板**：最厚材质（釉光 + 多层柔影 + 极淡暖金呼吸光晕），视觉权重最高。
- **L2 次级 · 美文卡 / 公告**：中等瓷感，略弱于 Hero。
- **L3 点缀 · 快捷入口 / 学科胶囊**：最轻，只用极淡底 + 发丝边，**不单独投影**，融入页面底色，像瓷盘上的纹样而非独立盒子。

### 2.3 品牌活力（温润中带沉稳活力，不死气沉沉）
- 保留"品牌光线母题"的**精神**但去其"廉价感"：Hero 顶部用**极淡暖金渐隐光泽**（非硬光线、非流光），叠加一个**比现版明显、但仍克制**的暖金呼吸光晕（`rgba(212,175,55,.18~.24)`、更大 blur、18s 缓动），让光晕成为"瓷盘后的暖光"而非"霓虹灯"。
- 点缀色：墨金主色（沉稳金 `#BA7517` / 亮金 `#D4AF37`）只用于**极小的强调点**（如分隔、图标、下划线），不铺大面。

### 2.4 字体根治方案（呼应 1.1 · 已按代码实证重写）
> 目标：让首页"早上好 / 用户名 / 各区块标题"的衬线呈现，与"各页 logo 小标题"**同一种好看质感**——即「小字 + 600 字重的优雅衬线」，且**首屏零闪烁**。

1. **消除首屏无衬线闪屏（核心修复）**：`index.html` 对 `noto-serif-sc-600.woff2`（展示主字重）与 `noto-serif-sc-700.woff2`（Hero 用）加
   `<link rel="preload" as="font" type="font/woff2" crossorigin href="/fonts/noto-serif-sc-600.woff2">`（800 文件保留但不预载，仅旧位用）。
   preload 让字体在 HTML 解析阶段就以最高优先级下载，**首屏绘制前已就位 → `swap` 的替补无衬线永远不显示**。字体仍是自托管、零 CDN。
2. **字重降到与 logo 同款优雅档**：墨金 `.hero-title`（含"早上好"+用户名）由 700–800 降为 **600**，字距从负追踪改为舒展 `letter-spacing:.01em`，`font-optical-sizing:auto`。这正是"logo 小标题好看"的同款处理（小字优雅衬线），Hero 只是字大但仍 600 优雅，不再"碑文笨重"。
3. **回退链加固**：`'Noto Serif SC','Source Han Serif SC','Songti SC','SimSun',serif`；保留 `font-display: swap`（配合 preload 后实测零闪，无衬线替补不会出现）。
4. **一致性**：问候语 / 用户名 / section-title / brand-name 全部继承同一条墨金衬线规则（L669），首屏不再有"有的有衬线有的没有"的割裂。
5. 经典模式**不碰衬线**（铁律1/14），仅墨金走瓷感衬线。

## 7. 输入框聚焦"橘色矩形框"排查与修复（独立 bug · 用户二次追问）

### 7.1 现象
部分输入框在聚焦 / 输入时，输入框周围（"上面盖一层"）出现**橘色矩形方框**。

### 7.2 根因（实测定位，非猜 · 已逐行核对 main.css）
- **全局 L193**：`:focus-visible { outline: 2px solid rgba(var(--zg-primary-rgb), 0.6); outline-offset: 2px; }` —— 给所有键盘聚焦元素加 2px 主色 outline + 2px 外偏移。
- **L194 漏项**：只把 `outline: none` 加给了 `.el-input__inner` 和 `.el-textarea__inner`，**漏了 `.el-input__wrapper` 和 `.el-select__wrapper`**。
- **实锤（Element Plus 2.8.4 源码）**：`node_modules/element-plus/es/components/input/src/input.mjs` L230 默认 `tabindex: 0` → **`.el-input__wrapper` 本身是可聚焦容器**（非仅内部 input）。聚焦 / 键入时它触发 `:focus-visible` → 套上 L193 的 outline。
- **关键 CSS 事实**：`outline` **不跟随 `border-radius`**，会渲染成**方块状**描边。输入框是圆角（10px），于是这圈橘色 outline 显示为"罩在输入框四周的**矩形方框**"——这正是用户描述的"橘色矩形方框"。
- 经典档 `--zg-primary-rgb: 245,158,11`（L31，**橘色**）→ 这圈 outline 就是**橘色矩形框** = 用户所见。
- 墨金档：`--zg-primary-rgb` 为金（L511: `186,117,23`）；墨金 L648 `.zg-inkgold :focus-visible { outline: 2px solid var(--zg-primary) !important }`（金 + `!important`）→ 墨金下 wrapper 会显示**金圈**，并与输入框自身 focus 内阴影（L744 `box-shadow ... var(--zg-primary) inset`）**叠加成矩形框**。
- **本质**：输入框已有专属 focus 内阴影光环（L172 / L744），却被全局 `:focus-visible` 再多套一圈 outline，于是出现"矩形框"。经典显橘、墨金显金，都是同一 bug。

### 7.3 修复（低风险 · 与首页重设计相互独立，可单独先行）
1. **排除输入框 wrapper 的 focus-visible outline**（输入框已有自身 focus 光环，不需 outline 双圈）。三处都需排除（墨金 L648 / L970 是 `!important`，须同权重覆盖）：
```css
/* 输入框已有自身 focus 内阴影光环，排除全局 :focus-visible 描边，避免叠加成橘/金矩形框 */
.el-input__wrapper:focus-visible,
.el-select__wrapper:focus-visible,
.el-textarea__inner:focus-visible { outline: none !important; }
.zg-inkgold .el-input__wrapper:focus-visible,
.zg-inkgold .el-select__wrapper:focus-visible,
.zg-inkgold .el-textarea__inner:focus-visible { outline: none !important; }
.zg-inkgold-dark .el-input__wrapper:focus-visible,
.zg-inkgold-dark .el-select__wrapper:focus-visible,
.zg-inkgold-dark .el-textarea__inner:focus-visible { outline: none !important; }
```
2. **（顺手）硬编码橘色改通道变量**（守铁律9，杜绝任何遗漏处出橘）：

## 9. 超级管理员网站自定义：双主题分套系统（用户本轮核心诉求）

### 9.1 检查结论（实测，非猜）
- **读取链路在墨金下已通**：`getSiteConfig`→`settings.ts`→`HomeView`/`NavBar` 无差别消费，墨金首页确实能读到所有自定义值——**不存在"墨金下不生效"的断点**。
- **但当前是单份全局配置，不是双主题**：`siteConfig` 只有一个对象（一份 `primaryColor`、一套 `quickLinks`、一套 `showXxx` 开关），经典改了覆盖墨金、墨金改了覆盖经典——**完全没有"两套"**。
- 后台已有**半吊子主题感知**：快捷入口图标快捷选择（`PRESET_EMOJIS`）按 `designMode` 在 `CLASSIC_EMOJIS`/`INKGOLD_EMOJIS` 间切换（SiteConfigView L137-141），但**数据仍是共享一份**。
- `primaryColor` 全局写入 `--zg-primary`（settings.ts L56）：墨金下若超管设了橙色，会跟金色学术主题打架——**墨金无法拥有独立主色**。

### 9.2 后端可行性（已查实 · 关键利好）
- `worker-api.ts` L2289-2333：`site_config` 以 **JSON 字符串存于 `settings` 表**（`INSERT OR REPLACE ... JSON.stringify(config)`），GET 时 `{ ...defaults, ...saved }` 合并。
- **结论：配置形状可自由扩展，无需任何数据库迁移**。双主题分套 = 把配置改为 `{ classic:{...}, inkgold:{...} }`；后端 PUT 原样存、GET 按主题合并即可，最多把 `defaults` 改成双主题默认。**纯前端 + 极小后端默认值调整，风险极低**。

### 9.3 设计方案（推荐：全量双主题分套）
- **数据结构**：`siteConfig = { classic: <完整配置>, inkgold: <完整配置> }`，每个主题各含现有全部字段（siteName/slogan/heroSubtitle/quickLinks/announcement/nav/布局/primaryColor 等）。
- **迁移（不丢数据）**：首次升级把现有单份配置分别拷入 `classic` 与 `inkgold`；后端 `defaults` 改为 `{ classic: defaultConfig(), inkgold: defaultConfig() }`，GET 合并按主题。
- **前台消费**：`settings.ts` 暴露 `activeSiteConfig` computed（按当前 `designMode` 取 `siteConfig.classic` / `siteConfig.inkgold`）；`HomeView`/`NavBar` 所有 `siteConfig.value?.xxx` 改为 `activeSiteConfig.value?.xxx`。
- **后台编辑（SiteConfigView）**：顶部加"编辑模式"切换（经典 / 墨金学术）；切换后表单加载对应主题子配置；保存时只更新对应子对象（如 `siteConfig.inkgold = {...}`）再整体 PUT。回显 / 增删改查 / 发布链路不变。
- **图标包**：快捷入口图标快捷选择继续按 `designMode` 切换（已有逻辑保留强化）。
- **primaryColor 分主题**：经典可保持橙、墨金可设金（或默认金），互不干扰——根治"墨金下橙色打架"。
- **铁律保障**：无论分套与否，`配置→保存→发布→前台生效→回显` 全链路正常；未自定义时走各主题皮肤默认。
