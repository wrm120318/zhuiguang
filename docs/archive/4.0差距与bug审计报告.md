## 二、未实施（Not Implemented）

### A4 · 输入框圆角统一 —— ❌ 未实施

**文档要求**（`追光界面设计改进报告4.0.md` L119–143）：在 `:root` 显式重置 Element Plus 圆角变量，再统一输入框圆角：

```css
:root {
  --el-border-radius-base: 8px;
  --el-border-radius-small: 6px;
  --el-border-radius-round: 999px; /* 仅按钮/胶囊用 */
}
/* .el-input__wrapper → 10px；.el-textarea__inner → 10px；.el-input__inner padding 0 12px */
```

**代码现状**（`src/styles/main.css`）：
- 全局 grep `--el-border-radius-base` / `--el-border-radius-small` / `--el-border-radius-round` → **0 命中**，`:root` 里从未定义这些 EP 变量。
- 当前只有 `.el-input__wrapper, .el-textarea__inner, .el-select__wrapper { border-radius: 12px !important }`（L131）的硬覆盖。
- `el-textarea` 的 `resize` 角标等组件仍继承外层 `--zg-radius`（18px），文档指出的「圆角过大/内容被覆盖」根因（EP 变量未重定义）**并未消除**。

**影响**：文档 A4 想解决的根因（EP 默认变量未接管导致个别组件圆角失控）仍然存在；而且当前输入框是 12px，文档要求统一到 10px 更紧凑。

**修复方向**：按文档 L131–143 在 `:root` 补三条 EP 变量重置 + 输入框 10px 圆角 + `show-word-limit` 不压字（纯 CSS，约 15 min，低风险）。

## 三、实施有误 / 改错（Wrongly Implemented）

### A2 · 学科图标 emoji→SVG —— ❌ 实施有误（映射语义错）

**文档要求**（L67–91）：16 个学科图标作为「一组」，整组统一风格（全 EP 或全自绘，绝不混搭）；每个映射语义准确、视觉好看；找不到合适的宁可保留 emoji 或自绘，**不能凑数**（铁律 5/6/7）。

**代码现状**：
1. 渲染管线本身在：`ZgGlyph.vue` 在墨金模式下把 emoji 映射成 EP SVG / 自绘 SVG，经典模式保留 emoji（符合设计）。
2. **但 `ZgGlyph` 映射表存在 4 处明确语义错误**（`src/components/ZgGlyph.vue`）：

   | 行 | emoji | 错映射 | 应为（语义准确） |
   | --- | --- | --- | --- |
   | L16 | `⚗`（化学/炼金） | `MagicStick`（魔法棒） | 自绘烧瓶/试剂瓶 SVG 或 `Switch` 类，绝不该是魔法棒 |
   | L36 | `🔬`（显微镜） | `MagicStick`（魔法棒） | `Search` / 自绘显微镜（EP 无显微镜，应自绘） |
   | L20 | `❤`（爱心） | `Medal`（奖牌） | EP 无 Heart，应保留 ❤ 或自绘心形（绝不该是奖牌） |
   | L25 | `🎭`（戏剧面具） | `Star`（星星） | 自绘面具/或 `Film`，不该是星星 |
   | L36 | `🔢`（数字键盘） | `Sort`（排序） | `Files`/`Operation`（文档 L87 已给建议），`Sort` 偏题 |

   其中 `❤→Medal` 最离谱：爱心直接显示成「奖牌」图标，信息完全错乱；`⚗️/🔬` 都塞成「魔法棒」是典型凑数。

3. **风格混搭隐患**：EP 图标是线性（outline）风格，而 `ZgGlyph` 的奖牌是自绘**填充**风格。同一套图标系统里「线性 + 填充」并存，跨组风格不统一，违反铁律 7（组内/跨组协调）。

4. `SubjectsAdminView.vue` L87 的 `iconPresets` 仍是 16 个 emoji 字符串源（靠 ZgGlyph 兜底转换，未改为更干净的预设），后台选图标时预览也走这套映射，错误映射会被原样展示。

**影响**：学科图标在墨金下会出现「化学=魔法棒、爱心=奖牌、戏剧=星星」等明显错误，正是用户说的「界面一堆 bug / 图标难看」。

**修复方向**：
- 立刻修正 5 处错映射（尤 `❤→Medal`、`⚗/🔬→MagicStick`），EP 没有的（爱心/显微镜/化学）改为「整组自绘 SVG」或保留单色 emoji，禁止凑数。
- 统一 16 学科图标的风格（全 EP 线性 / 全自绘，二选一并跨组一致）。
- 改完后三档（经典/墨金浅/墨金深）目视回归。

### A5 · 登录卡片阴影 —— ❌ 实施有误（单层重黑影 + 深色缺规则）

**文档要求**（L145–153）：登录卡片用「**双层柔和阴影 + 顶部高光描边**」替代单层大阴影，三档都要有层次、不能有「悬浮在黑洞里」的质感。

**代码现状**（`src/views/LoginView.vue`）：
- L129 墨金浅色：
  ```css
  .zg-inkgold .login-card { border: 1px solid rgba(212,175,55,0.22) !important;
    box-shadow: 0 28px 80px rgba(0,0,0,0.55) !important; }
  ```
  → **单层重黑影 `0 28px 80px rgba(0,0,0,0.55)`**，无顶部高光、无双层结构，正是文档点名的「又大又重的黑影子」没改掉。
- **墨金深色（`.zg-inkgold-dark .login-card`）完全没有任何自定义规则** → 继承通用样式，深色模式下卡片无高光、质感塌陷（死黑块）。

**影响**：登录页在墨金两档下阴影「不自然」，深色档尤其糟——与文档 A5 目标完全相反。

**修复方向**：按文档「双层阴影 + 高光描边」规范，给浅色/深色分别写 `.login-card` 规则（如 `0 20px 50px rgba(120,90,30,.18), 0 2px 0 rgba(255,255,255,.25) inset` 之类的高光内描边），深色档补一条，三档回归。

## 四、实施有偏差（Deviation，非硬 bug）

### A7 · 首页/学科图标统一暖金浅底 —— ⚠️ 偏差

**文档要求**（L221–244）：默认状态（后台未自定义 `color`）图标容器用**浅金底** `background: rgba(245,158,11,0.10)` + 金色图标；**只有后台自定义了 `color`** 才走 `linear-gradient(135deg, ${color}, ${color}aa)` 实色渐变（守铁律 4，自定义照常生效）。

**代码现状**（`src/views/SubjectsView.vue` L29–36 / `HomeView.vue` 同构）：
```js
function iconBg(color?: string) {
  const def = inkgold ? (dark ? '#D4AF37' : '#BA7517') : '#F59E0B'
  const c = color || def
  return `linear-gradient(135deg, ${c}, ${c}aa)`  // 永远是实色金渐变
}
```
- 即使后台**未自定义** `color`，也返回**实色金渐变**（第二停 50% alpha），而非文档要求的 `rgba(245,158,11,0.10)` 浅底。
- `HomeView` 的 `defaultQuickLinks` 仍带 4 种不同金色调（`#F59E0B/#FBBF24/#FB923C/#FDE68A`），与文档「统一默认暖金浅底」不一致。

**影响**：默认态比文档预期更饱和、更「实」，在墨金（尤其深色）下每个图标背后都是一块 50% 金渐变，视觉偏重、不够克制。功能上**自定义颜色仍正常生效（铁律 4 满足）**，所以这是「美观偏差」不是「功能 bug」。

**修复方向**：把默认分支改为 `rgba(245,158,11,0.10)`（墨金用 `rgba(186,117,23,0.10)` / `rgba(212,175,55,0.10)`），仅当用户/后台给了 `color` 才用实色渐变——与文档 L235–244 完全一致。
