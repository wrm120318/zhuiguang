# B2 存储运维文档（v4.4.0）

> 配套「追光学科共享平台」文件存储迁移至 Backblaze B2 私有桶。
> 阅读对象：超管 / 运维。普通用户无需阅读。

---

## 一、架构现状

```
浏览器 → Cloudflare Worker(worker-api.ts) → Backblaze B2 私有桶(zhuiguang-k12-004)
            ↑ 全部上传/下载/鉴权代理都走这里，浏览器永不直连 B2
D1(file_meta 等表) = 文件元数据唯一来源（不调 B2 List，不运行时校验存在）
```

- **桶**：`zhuiguang-k12-004`（allPrivate 私有桶）
- **后端模式**：`B2_FREE`（默认，不绑卡，0 元/年，目标 10GB）
- **切换**：环境变量 `STORAGE_MODE` = `B2_FREE` / `B2_PAID` / `SUPABASE`，可一键回滚。代码永不自动切付费。

---

## 二、已知限制（务必知悉）

1. **下载速度取决于 CF 缓存命中率**。缓存命中 = CF 边缘节点直接返回，快；缓存未命中（首次下载 / 缓存被驱逐）= 回源 B2 海外源站，慢。这是架构固有现象，**无法彻底消除，只能靠缓存缓解**。
2. **B2 免费账户会随机出现 429 限流**（与配额无关），表现为偶发上传/下载失败。前端已做友好提示，重试即可。
3. **B2 免费模式当日 B 类读请求打满 2500**：已缓存旧文件正常访问；**当日新上传文件无法下载/预览，UTC 零点自动恢复**。
4. **D1 写满会让整个站点全部业务瘫痪**（不只是文件功能），需定期关注 D1 用量。
5. **官方配额字段在本账户不可用**：见第三节。

---

## 三、配额统计说明（重要）

需求要求「配额从 B2 官方拉取」，但实测 B2 免费账户：

- 单次下载响应**不返回**官方头 `b2-api-b-class-transaction-count-today`（CDN `downloadUrl/file/...` 与 API `b2_download_file_by_id` 两种方式均验证为 `null`）；
- 主密钥能力清单**无 `readAccountInfo`**，`b2_get_account_info` 返回 404。

→ 因此「当日 B 类交易数」这一官方字段在**本账户无法取得**。

**处理方式（已与用户确认方案3）**：系统**不做任何自算猜测**，而是每次 Worker **真实回源 B2** 时在 D1 记一笔「今日真实回源次数」（真实发生的请求，非估算），监控面板**明确标注「本地统计（非官方）」**。软上限/告警基于该真实回源次数判断。

> 若未来升级为可拿官方配额的 B2 账户/密钥，可在 `storage-layer.ts` 的 `serveFileById` 第6步改为读取官方头并 upsert，无需改表结构。

**官方可用数据**：桶占用（`b2_list_buckets` 的 `totalSize` / `fileCount`）为官方桶级摘要，正常展示，且**不违反「禁调 B2 List 文件」约束**（桶级摘要 ≠ 列举文件）。

## 四、禁止事项

- 🚫 **禁止直接登录 B2 后台手动增删改文件**。所有文件操作必须经 Worker，否则 D1 元数据与 B2 对象会不一致，导致文件"存在却打不开"或"已删却还能下"。
- 🚫 禁止在下载链路加同步重型计算 / 二次复制文件流。
- 🚫 后端 Worker **不做任何图片处理**（不转码、不压缩），图片 WebP 转码只在浏览器前端执行。
- 🚫 禁止原地覆盖文件：更新必生成新 fileId。

---

## 五、备份要求

- B2 桶本身有版本/生命周期，但**本系统不依赖 B2 版本做回滚**。重要教学资料上传后，建议超管定期通过 B2 控制台或 `rclone`/`b2` CLI 做桶级备份到异地。
- 迁移前请确保 Supabase 上的旧文件**未被删除**（迁移是"复制"而非"移动"，旧文件保留作兜底）。

---

## 六、监控面板怎么看（管理后台 → 运行监控 → 存储优化）

- **当前存储后端**：B2_FREE / B2_PAID / SUPABASE。
- **B2 回源统计（本地统计·非官方）**：今日真实回源次数 / 告警阈值（默认 2200）/ 免费上限参考 2500。
- **官方桶占用**：桶文件数、桶已用字节（来自 B2 官方）。
- **缓存命中率**：越高越好，直接决定下载速度。
- **各用户当日真实回源 TOP**：排查爬虫 / 异常刷量。
- **WebP 转换数 / 体积**：前端转码成效。
- **下载耗时**：缓存命中均值 vs 回源均值。

> 监控仅页面内告警，**无邮件/推送**。超管需**定期主动查看**监控面板。当回源逼近上限时，面板输出告警，处理方案：清理冷文件、优化缓存 TTL、或切换其他存储后端。

---

## 七、人工测试校验清单（上线后必做）

1. 新上传图片强制输出 WebP，画质无损（对比原图文字清晰）。
2. PDF / Word / Excel / PPT **完全不被转码篡改**（二进制一致，可 diff）。
3. 历史存量图片迁移后维持原格式，不自动转 WebP。
4. B2 回源统计 / 告警 / 降级功能校验。
5. 文件下载流式转发：大文件（>10MB）不会占满 Worker 内存；缓存命中下载速度明显优于回源。

---

## 八、故障行为速查

| 现象 | 原因 | 处理 |
|---|---|---|
| 新文件当日无法下载，旧文件正常 | 免费额度 B 类打满 2500 | 等 UTC 零点恢复；或清理冷文件降回源 |
| 偶发上传/下载失败 | B2 免费账户随机 429 | 前端重试即可 |
| 首次下载慢、刷新后快 | 缓存未命中→回源海外 | 正常；可对热门文件用预热接口 |
| 整站瘫痪 | D1 写满 | 紧急清理 D1 / 扩容 |
| 监控「B2 回源统计」标注"非官方" | 本账户无官方配额字段 | 正常，属方案3设计 |

## 九、常用运维命令

```bash
# 部署 Worker（需在本机，有 CF 凭证）
CLOUDFLARE_API_TOKEN=xxx npx wrangler deploy

# D1 建表（首次）
npx wrangler d1 execute zhuiguang-db --remote --file=migrations/0001_b2_storage.sql

# 存量迁移 Supabase→B2（超管调用，分批）
curl -X POST https://<你的worker域名>/api/admin/migrate/to-b2 \
  -H "Authorization: Bearer <超管token>" \
  -H "Content-Type: application/json" \
  -d '{"limit":50}'
# 重复调用直至 done+failed+skipped 覆盖全部 total

# 预热热门文件（超管）
curl -X POST https://<你的worker域名>/api/admin/prewarm \
  -H "Authorization: Bearer <超管token>" \
  -H "Content-Type: application/json" \
  -d '{"fileIds":["abc123","def456"]}'
```
