把代码推送到 GitHub 约 2 分钟

为什么要做这步？ Render 部署需要从 GitHub 拉取你的代码，所以代码得先传到 GitHub。

① 在 GitHub 网站上创建一个空仓库：

  1. 打开 🔗 github.com/new
  2. Repository name 框里填：zhuiguang（名字随便，这个只是建议）
  3. Description（描述）：可填可不填
  4. 选 Public（公开）或 Private（私有）都行，Private 更安全
  5. ⚠️ 关键：不要勾选任何 "Add a README" / "Add .gitignore" / "Choose a license"
    （因为项目里已经有这些文件了，勾了会冲突）
  6. 点页面最下面绿色按钮 Create repository
创建完会跳到一个页面，上面写着 "…or push an existing repository from the command line"
下面有一段类似这样的代码（不要急着复制 GitHub 给你的，用我下面这段更稳）。

② 在你电脑上，打开项目文件夹，右键 → 打开终端（或 PowerShell / CMD）：

确保你在项目根目录（能看到 package.json 的那个目录），然后复制下面 3 行命令粘贴执行：

📋 点我展开命令（把 <你的用户名> 换成你的 GitHub 用户名） 
git remote add origin https://github.com/<你的GitHub用户名>/zhuiguang.git
git branch -M main
git push -u origin main
💡 举个例子：如果你的 GitHub 用户名是 zhangsan，那第一行就是：
git remote add origin https://github.com/zhangsan/zhuiguang.git

③ 第一次推送时会弹出 GitHub 登录框，按提示登录或粘贴 Personal Access Token 即可。

✅ 怎么算成功？刷新你 GitHub 仓库网页，能看到项目所有文件（package.json、server/、src/ 等）就对了。
2

注册 Turso（云端数据库，免费 9GB）约 2 分钟

为什么要做这步？ 网站的所有数据（用户、文章、题库等）都要存数据库。Render 免费实例没有持久磁盘，所以数据库得放在 Turso 这种专门的云数据库服务上，免费 9GB 够用很久。

① 打开 Turso 官网注册：

🔗 打开 turso.tech

→ 点右上角 Sign up 或 Login → 用 Sign in with GitHub（推荐，一键登录，免得再记一个密码）

② 创建一个数据库：

  1. 登录后进入控制台，点 Create Database（或 New Database）
  2. Database Name：填 zhuiguang（随便填，建议这个）
  3. Group / Location：选离你最近的（中国用户选 Singapore 或 Tokyo）
  4. 点 Create

③ 复制数据库 URL（第一个要粘贴到 Render 的值）：

  1. 创建完会跳到数据库详情页，能看到一串 libsql://zhuiguang-xxx.turso.io
  2. 点旁边的 复制按钮（或手动选中复制）
第 1 个值：TURSO_DATABASE_URL
形如 libsql://zhuiguang-xxxx.turso.io
先记着，待会儿步骤 5 要粘贴

④ 创建访问 Token（第二个要粘贴到 Render 的值）：

  1. 在数据库详情页，找 "Create Token" 或 "Access Tokens" 按钮
  2. 选 Full Access（完整访问）→ 点 Create
  3. 会显示一长串字符（以 eyJ... 开头），立刻复制（⚠️ 只显示一次，关掉就看不到了）
第 2 个值：TURSO_AUTH_TOKEN
形如 eyJhbGciOi...
先记着，待会儿步骤 5 要粘贴
⚠️ 注意：
  • Token 只显示一次，没复制对的话重新创建一个就行（旧的会失效）
  • URL 必须是 libsql:// 开头，不是 https://
3

注册 Supabase（文件存储，免费 1GB）约 3 分钟

为什么要做这步？ 用户上传的头像、附件、图片都要存文件。Render 没有持久磁盘，所以文件得放在 Supabase 的对象存储里，免费 1GB 够小站用。

① 打开 Supabase 官网注册：

🔗 打开 supabase.com

→ 点右上角 Start your project → 用 Continue with GitHub 一键登录

② 创建一个项目：

  1. 点 New Project
  2. Organization：默认就行（首次会让你建一个组织，名字随便填）
  3. Project Name：填 zhuiguang
  4. Database Password：点 Generate a password 自动生成（记下来，虽然我们不用它，但万一以后直连数据库会用到）
  5. Region：选 Singapore（东南亚，中国访问最快）
  6. Pricing Plan：选 Free
  7. 点 Create new project
⏳ 现在等 1-2 分钟，Supabase 在初始化项目。页面会显示 "Setting up project..."，等顶部状态变成绿色 "Ready" 再继续。

③ 创建存储桶 Bucket（关键！这步做错文件就传不上去）：

  1. 左侧菜单找 Storage（带数据库桶图标的那个）→ 点进去
  2. 点右上角 New bucket 按钮
  3. Bucket name：填 zhuiguang-files（必须一模一样，包括横线）
  4. Public bucket：勾选它！（不勾选的话前端打不开图片）
  5. 其它选项不用动，点 Create bucket
⚠️ 检查：创建完应该在 Storage 列表里看到一个名为 zhuiguang-files 的桶，旁边有 "Public" 标签。
如果没有 Public 标签 → 点进 bucket → Settings → 勾上 Public → Save。

④ 复制 Project URL（第三个要粘贴到 Render 的值）：

  1. 左侧菜单最底下点 Settings（齿轮图标）
  2. 点 API
  3. 找到 Project URL，复制它（形如 https://xxxxx.supabase.co）
第 3 个值：SUPABASE_URL
形如 https://xxxxx.supabase.co
先记着，待会儿步骤 5 要粘贴

⑤ 复制 service_role Key（第四个要粘贴到 Render 的值）：

  1. 还在刚才的 Settings → API 页面
  2. 往下滚到 "Project API keys" 区域
  3. 会看到两个 key：anon public（短）和 service_role（长）
  4. 找到 service_role 那一行 → 点 Reveal（显示）→ 复制那一长串
第 4 个值：SUPABASE_SERVICE_KEY
形如 eyJhbGciOiJIUzI1NiIs...
先记着，待会儿步骤 5 要粘贴
⚠️ 3 个最容易踩的坑：
  • Bucket 必须是 Public：否则用户上传的图片打不开
  • 用 service_role key，不是 anon key：anon key 权限不够，上传会报 403 错误
  • service_role key 千万别泄露到前端代码里：它有完全权限，只在后端用
4

在 Render 创建 Web Service 约 1 分钟

为什么要做这步？ Render 是托管平台，它会自动构建你的项目并运行，提供一个公网可访问的网址。

① 打开 Render 注册登录：

🔗 打开 Render 控制台

→ 右上角 Get Started / Sign Up → 用 GitHub 登录（推荐，会自动关联你的仓库）

② 新建一个 Web 服务：

  1. 登录后进入 Dashboard，右上角点 New → 选 Web Service
  2. 会弹出 GitHub 授权，授权 Render 访问你刚推送的 zhuiguang 仓库
  3. 找到并选中 zhuiguang 仓库 → 点 Connect

③ 确认配置（Render 会自动读取 render.yaml，基本不用改）：

Name：zhuiguang（这个会成为域名前缀，可改）
Runtime：Node
Region：Singapore（或 Oregon，看哪离你近）
Branch：main
Root Directory：留空
Build Command：npm install --include=dev && npm run build
Start Command：npm run start
Instance Type：Free

确认无误后，点页面底部 Apply 或 Create Web Service 按钮。

💡 此时 Render 会开始构建，但下一步要填环境变量，别等它构建完，马上继续下一步。
5

填环境变量（最重要的一步）约 3 分钟

为什么要做这步？ 程序启动时需要知道数据库地址、文件存储地址这些敏感信息，这些不能写死在代码里，得通过"环境变量"传给程序。不填程序会启动失败。

① 找到环境变量设置入口：

  1. 在你的 Render 服务页面，点左侧菜单 Environment（或先点服务名 → 再点左边 Environment 标签）
  2. 会看到 "Environment Variables" 区域，有一个 Add Environment Variable 按钮

② 一条一条添加下面 5 个变量（点 Add Environment Variable → 填 Key 和 Value → Save → 再加下一条）：

Key: TURSO_DATABASE_URL
Value: 第 2 步拿到的 libsql://...
Key: TURSO_AUTH_TOKEN
Value: 第 2 步拿到的 eyJ...
Key: SUPABASE_URL
Value: 第 3 步拿到的 https://xxx.supabase.co
Key: SUPABASE_SERVICE_KEY
Value: 第 3 步拿到的 service_role key
Key: SUPABASE_BUCKET
Value: zhuiguang-files（手打这个）

③ 关于 JWT_SECRET（不用手动填）：

render.yaml 里已经写了 generateValue: true，Render 会自动给你生成一个随机密钥。如果你在环境变量列表里已经看到 JWT_SECRET，就不用管它；如果没有，手动 Add 一条，Value 随便填一串 32 位以上的字符。

💡 填完之后：点 Save Changes，Render 会自动触发重新构建（因为环境变量变了）。
6

等部署完成 2-5 分钟

① 看构建日志：

  1. 在你的 Render 服务页面，顶部有几个 tab：Dashboard / Logs / Settings 等
  2. 点 Logs（日志）
  3. 会看到滚动的日志，先显示安装依赖、构建前端，最后启动服务

② 看到下面这两行 = 成功了：

[storage] Supabase Storage 模式：文件存于云端 bucket
[server] 追光后端运行于 http://localhost:xxxx

③ 服务页面顶部状态：

  • 构建中：Building（黄色，转圈）
  • 部署中：Deploying（黄色）
  • Live（绿色圆点）= 部署成功，可以访问了 🎉
  • Failed（红色）= 出错了，看下面排查
❌ 构建失败怎么排查？
  • "TURSO_DATABASE_URL" is not set → 第 5 步环境变量没填，回去补
  • ETIMEDOUT / connection refused → Turso URL 或 Token 填错，回 Turso 控制台重新复制
  • Supabase 403 / unauthorized → service_role key 填成了 anon key，回 Supabase 重新复制 service_role 那个
  • Build failed → 把错误日志截图发我，我帮你看
💡 关于 Render 免费版：
  • 15 分钟没人访问会自动休眠，下次打开要等 10-30 秒冷启动
  • 每月 750 小时免费时长，单个服务够用

常见问题

Q: 为什么打开网站很慢 / 第一次要等很久？

Render 免费版 15 分钟没人访问会休眠，下次访问要 10-30 秒"冷启动"唤醒。这是正常的，不是 bug。介意的话升级 Starter 套餐（$7/月）。

Q: 数据会丢吗？重启后还在吗？

不会丢。 数据存在 Turso 云数据库，文件存在 Supabase，都不在 Render 上。Render 实例重启、重新部署，数据和文件都还在。

Q: 想要自定义域名怎么办？

Render 服务页面 → Settings → Custom Domains → Add Custom Domain → 按提示在你域名 DNS 加一条 CNAME 记录指向 Render 给的地址。Render 自动配 HTTPS。

Q: 我想改代码后怎么更新？

本地改代码 → git add . && git commit -m "xxx" && git push → Render 检测到 push 会自动重新构建部署，全程不用你操作 Render。

Q: Turso / Supabase 免费额度够用吗？

小站（几百用户）完全够用：Turso 免费 9GB 数据库，Supabase 免费 1GB 文件 + 50MB/月 API 流量。用超了再升级，一个月几美元。

Q: 部署失败，日志看不懂怎么办？

把 Render 的 Logs 页面错误信息截图发我，或把错误那几行文字复制给我，我帮你定位。

Q: 可以部署到自己的服务器吗？

可以！项目根目录有 deploy.sh 一键脚本，在 Ubuntu/Debian 服务器上跑 sudo bash deploy.sh 就行（自动装 Nginx + HTTPS + systemd 守护）。但 Turso + Supabase 还是要配，因为它们存数据和文件。
