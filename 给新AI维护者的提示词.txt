【项目基本信息】
================================================================================

- 项目名称：追光 · 学科共享平台
- 当前版本：v2.1.19
- 技术栈：Vue 3 + TypeScript + Vite + Element Plus
- 后端框架：Hono（Cloudflare Workers）
- 数据库：Cloudflare D1（SQLite兼容）
- 文件存储：Supabase Storage
- 前端部署：Cloudflare Pages（自动构建）
- 后端部署：Cloudflare Workers（wrangler deploy）
- 网站域名：https://xkzg.de5.net
- API域名：https://api.xkzg.de5.net
- GitHub仓库：https://github.com/wrm120318/zhuiguang

================================================================================
【核心铁律（每次改动前必默念）】
================================================================================

① el-upload 必须用 :http-request="customRequest"，禁止用 :before-upload
② 大文件（>100KB）必须走 Supabase presign URL 直传，禁止走后端
③ server/index.ts 中给静态资源加 ?v=时间戳 的代码禁止删除/修改
④ 角色名 SUPER_ADMIN/TEACHER/STUDENT 禁止改名/加新角色
⑤ 登录积分同一天只给1次，禁止改成每次都给
⑥ 站内信联系人列表必须展示全部活跃用户（除自己），禁止限制为"仅超管"
⑦ 学生上传的资料/美文必须显示 pending 状态（待审核小标签）
⑧ 部署命令：后端 npx wrangler deploy，前端 git push origin main
⑨ 改代码前先 source /workspace/.env 加载凭证
⑩ 发布后必须打开 https://xkzg.de5.net 实际验证，不要只说"改好了"

【数据库操作】
   npx wrangler d1 execute zhuiguang-db --remote --command="SQL语句"

【查看日志】
   npx wrangler tail --format=json 2>&1 | head -50

【回复格式要求】
================================================================================

每次改完代码后，按以下格式回复用户：

（1）改了什么（3句话以内）
（2）改了哪几个文件（列绝对路径）
（3）前端代码已推送 / 后端已部署 / 数据库已更新（根据情况选择）
（4）怎么验证（给我用户操作步骤）
（5）有没有副作用

示例：
（1）修复了学生上传美文后列表不显示的问题，改为加载 pending 状态内容。
（2）改了 src/views/article/ArticleListView.vue 第 45 行，添加了 status 参数判断。
（3）前端代码已推送到 GitHub，Pages 正在自动构建。
（4）打开 https://xkzg.de5.net → 用学生账号登录 → 上传一个 PDF → 列表中应显示"待审核"标签。
（5）无。

【碰架构类需求的处理流程】
================================================================================

涉及以下需求时，先写评估报告，等用户确认后再动手：
   - 换部署平台 / 换数据库 / 换存储
   - 改项目结构 / 换框架
   - 新增需要注册账号/绑卡/充值的服务

评估报告内容：
   ① 方案优点和缺点（如实说，不能只说优点）
   ② 是否影响现有数据（要迁移还是不迁移）
   ③ 用户需要做什么操作
   ④ 风险点（服务商稳定性、收费政策等）
